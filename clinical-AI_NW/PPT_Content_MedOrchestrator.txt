SLIDE 3: PROJECT OVERVIEW
================================================================================

Project Overview

EXECUTIVE SUMMARY
━━━━━━━━━━━━━━━━━━
MedOrchestrator is an AI-powered clinical decision-support platform that 
orchestrates multiple specialized agents to analyze patient symptoms, lab 
results, and medications in parallel — producing differential diagnoses, 
evidence-based treatment recommendations, and drug-safety alerts under 
clinician supervision.


PROBLEM STATEMENT
━━━━━━━━━━━━━━━━━━
• Clinicians face information overload when diagnosing complex conditions
• Manual correlation of symptoms, lab values, and drug interactions is 
  time-consuming and error-prone
• Delayed diagnosis impacts patient outcomes and increases healthcare costs
• No integrated system exists to combine multiple clinical data sources 
  intelligently


OBJECTIVE
━━━━━━━━━━━━━━━━━━
• Build a multi-agent AI system that runs analyses in parallel for speed
• Provide ranked differential diagnoses with confidence scores and reasoning
• Generate guideline-aligned treatment plans with dosing and monitoring
• Flag drug interactions and critical lab values automatically
• Surface dissenting opinions when agents disagree for clinical transparency

SETUP INSTRUCTIONS
━━━━━━━━━━━━━━━━━━

1. Clone the repository:
   ┌──────────────────────────────────────────────────────────────┐
   │ git clone https://github.com/Om-Shankar-Thakur/              │
   │           clinical-ai-multiagent.git                         │
   │ cd clinical-AI_NW                                            │
   └──────────────────────────────────────────────────────────────┘

2. Create virtual environment:
   ┌──────────────────────────────────────────────────────────────┐
   │ python -m venv venv                                          │
   │ venv\Scripts\activate        # Windows                       │
   └──────────────────────────────────────────────────────────────┘

3. Install dependencies:
   ┌──────────────────────────────────────────────────────────────┐
   │ pip install -r requirements.txt                              │
   └──────────────────────────────────────────────────────────────┘

4. Configure environment (.env file):
   ┌──────────────────────────────────────────────────────────────┐
   │ AZURE_OPENAI_API_KEY=your-api-key                            │
   │ AZURE_OPENAI_ENDPOINT=https://your-resource.openai.azure.com/│
   │ AZURE_OPENAI_API_VERSION=2024-02-15-preview                  │
   │ AZURE_OPENAI_DEPLOYMENT=your-deployment-name                 │
   └──────────────────────────────────────────────────────────────┘

5. Ingest data (first time only):
   ┌──────────────────────────────────────────────────────────────┐
   │ python rag/ingest.py                                         │
   └──────────────────────────────────────────────────────────────┘

INTRODUCTION TO SOLUTION
━━━━━━━━━━━━━━━━━━━━━━━━
MedOrchestrator uses 4 specialized AI agents coordinated by an orchestrator:

1. 🔍 Symptom Analyzer — semantic search over disease database
2. 🧪 Lab Interpreter — rule-based critical value detection
3. 💊 Treatment Planner — RAG retrieval + LLM guideline formatting
4. ⚠️ Drug Interaction Checker — LLM safety review


WHAT IT DOES (DETAILED)
━━━━━━━━━━━━━━━━━━━━━━━

Input: Chief complaint, symptoms, lab values, current medications
       │
       ▼
Step 1: Symptom Analyzer + Lab Interpreter run IN PARALLEL
        (ThreadPoolExecutor with 2 workers)
       │
       ▼
Step 2: Orchestrator ARBITRATES diagnosis
        (55% symptom score + 45% lab score weighted merge)
       │
       ▼
Step 3: Treatment Planner retrieves guidelines via FAISS
        LLM formats into structured management options
       │
       ▼
Step 4: Drug Interaction Checker validates against medications
        Flags contraindications with severity levels
       │
       ▼
Output: JSON report with diagnosis, confidence, treatment plan,
        drug warnings, critical flags, dissenting opinions


ASSUMPTIONS
━━━━━━━━━━━
• Access to Azure OpenAI API for LLM capabilities
• Disease database covers common conditions (50+ diseases)
• Clinical guidelines are preprocessed and chunked for RAG
• Lab rules configured for common parameters (platelets, hemoglobin, etc.)
• Final clinical decisions remain with licensed clinicians


TECHNICAL DETAILS — WHY THESE COMPONENTS?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

┌─────────────────────┬──────────────────────────────────────────────┐
│ Component           │ Reason                                       │
├─────────────────────┼──────────────────────────────────────────────┤
│ FAISS over Pinecone │ Local execution, no external API costs, fast │
│ Sentence-BERT       │ 5× faster than BERT, 384-dim efficient       │
│ FastAPI over Flask  │ Native async, Pydantic validation, auto-docs │
│ ThreadPoolExecutor  │ Simpler for CPU-bound agent work             │
│ Weighted (55/45)    │ Symptoms more reliable than partial labs     │
│ Threshold (0.4)     │ Prevents plans for uncertain diagnoses       │
└─────────────────────┴──────────────────────────────────────────────┘
